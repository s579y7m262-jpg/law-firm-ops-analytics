# data/ — 数据接入说明

原始数据不入仓（`.gitignore` 已排除 `data/raw/*`）。要让脚本跑起来，把 CRM 导出的文件按下面的名字放进 `data/raw/`。

## 1. 需要的文件

| 文件名 | Sheet | 粒度 | 必需字段 |
|---|---|---|---|
| `订单表_2026.1-2026.9.xlsx` | `订单导出明细` | 一行 = 一次约见 / 一个案件 | `订单编号` `案件编号` `合同总金额` `成交时间` `约见时间` `约见类型` `差旅费金额` `费用支付时间` `首期认款金额` `订单归属人` `是否合作约见` `约见归属人1` `约见归属人1个数` `约见归属人2` `约见归属人2个数` |
| `订单表_2026.10.xlsx` | 同上 | 同上 | 同上（按月份分开导出，脚本会合并） |
| `收入表_2026.1-2026.10.xlsx` | 每月一个 sheet | 一行 = 一笔认款 | `案件编号` `款项类型`（新接 / 新接案件 / 新接案件-撞单 / 中期尾款 …）`业绩金额` `所属小组` `所属公司` `月份` |
| `花名册.xlsx` | 首表 | 一行 = 一名员工 | `坐席`（姓名）`小组` `区域` `在职状态` |
| `给数据组结案，退费，返点汇总表10-30.xlsx` | 每月一个 sheet | 混装三类 | 第 11/12/13 列（板块判定见 [../docs/05](../docs/05-data-quality.md) §A-8） |

> 字段名必须一致。源表可能有 166 列，脚本只读上表列出的那些；其余列不影响运行。
> **收入表的列名每月会漂移**（`提成比例`→`业绩比例`→`业绩比例备注`，8/9 月 `所属公司`/`区域` 位置对调），脚本按列名对齐，所以列序变化不影响——但也正因如此，**改列名会直接报错，属于预期行为**。

## 2. 区域代号

仓库内所有区域都是代号，脚本默认 `A区,B区,C区,D区`。两个办法接真实数据：

```bash
# 办法一：环境变量（推荐，不改代码）
REGIONS="你的区域1,你的区域2,你的区域3,你的区域4" python src/etl/build_gold.py
```

```python
# 办法二：改 src/etl/build_gold.py 里的默认值
REGIONS = ["...", "...", "...", "..."]
```

如果小组名不以区域名开头（例如「河北…组」要归到某个区域），在 `data/raw/region_alias.json` 里配别名：

```json
{ "D区": ["河北"] }
```

该文件属敏感信息，同样不入仓（见 `region_alias.example.json`）。

## 3. 复现检查

跑完 `src/etl/build_gold.py` 后，控制台应打印出 KPI 与 DQ（数据质量）清单。用它自检：

- `件数按业绩比例拆分 … 拆分后件数合计 X 件，案件 X 个` —— 两个 X 必须相等，这就是"每案恰 1 件"的恒等式。
- 区域表的 `case_count` 五列相加 = 总件数；`revenue` 五列相加 = 总收入表合计。
- 若出现 `咨询费未映射到小组` 比例过高，说明花名册的「小组」与收入表的「所属小组」不是同一套命名，需要先对齐组织维表。
