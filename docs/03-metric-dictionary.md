# 03 指标口径字典

> 这个项目真正的产品不是看板，是这张表。任何一次"数字对不上"，追到最后都是某一行定义不同。

## 1. 核心指标

时间窗口：2026-01-01 ~ 2026-10-27（收入表最后一笔认款）。金额单位元，展示时转万元。

| 指标 | 定义 | 公式 | 2026.1–10 |
|---|---|---|---|
| 总业绩 | 收入表「业绩金额」**全部行**求和，不剔重 | `Σ 业绩金额` | **9,713.7 万** |
| 成案量 | 「新接」类记录按案件编号去重，撞单按业绩比例拆 | `Σ V`（见 §4） | **1,115 件** |
| 成案金额 | 「新接」类记录**按行**求和（撞单拆给多组即相加） | `Σ 新接金额` | **8,237.4 万** |
| 客单价 | 成案金额 ÷ 成案量（加权，不是月度算术均值） | `8,237.4万 / 1,115` | **73,878 元** |
| 咨询费 | 差旅费驱动的线索条数（三规则并集） | 见 §5 | **1,064 条** |
| 订单内成案率 | 成案数 ÷ 有约见的订单数（V1 订单表口径，1–9 月） | — | 80.5% |
| 差旅费线索成案率 | 差旅费线索中最终成案的比例（V1 口径，1–9 月） | — | 77.3% |
| 退费率 | 退费金额 ÷ 当月业绩 | — | 7.9%（4.2%–14.6%） |

### 命名陷阱

- **咨询费不是"收入"**，是"这条线索产生了差旅费/主场接待成本"，是**投入指标**。
- 咨询费口径自带循环：三规则中有两条要求"已成案"，导致咨询费 975 ≈ 成案 972，`成案/咨询费` 会出现 >100% 的荒谬结果。**这个比值不是转化率**，已弃用，改用「订单内成案率」「差旅费线索成案率」。

## 2. 撞单：本项目最大的口径分歧

同一案件被两个小组共同承接时，收入表按小组拆成多行，都标注「-撞单」。这批行怎么算，直接决定业绩是 7,130 万还是 9,713 万。

| 算法 | 总业绩 | 判断依据 | 结论 |
|---|---|---|---|
| A. 按案件去重取单笔最大 | 7,130.6 万 | 拿订单表「首期认款金额」反向校验，单笔最大值与首期中位差 0 | ❌ 基准错配，已废弃 |
| B. 全部行求和 | 9,713.7 万 | 拿合同总金额校验：求和 vs 合同额中位差 0、完全一致率 56.8% | ✅ **采用** |

**A 错在哪**：首期认款常是合同额的一半，拆分后每组各记一份首期，取最大值恰好等于首期——"完全吻合"是假象。
换合同额做锚点后立刻分开：求和一致率 56.8%，取最大值一致率只有 0.6%、中位差 6.2 万。

> **通用教训：跨表校验时，校验基准必须与被校验指标同义、同粒度。用「首期」校「全额」是基准错配，得到的"完美吻合"最危险。**

## 3. 金额按行、件数按主责

拆分导致金额可以分散到多组，但**件数不能重复计**。所以：

- **金额**：按各行实际归属（真实业绩分配）。
- **件数**：按业绩比例分摊到各行所在组 → 区域件数之和恰好 = 1,115，可对账。
- 副作用：区域客单价被略微高估（分母只算份额），已在看板脚注声明。

小数件数（如 196.9 件）不是错误，是设计结果；脚注直写"共同承接的案件按业绩占比分配件数，故有小数"。

## 4. 件数拆分公式

参考表（财务提供的《成案量口径》）用 Excel 实现，逻辑如下：

```excel
W = SUMIFS(K:K, F:F, F2, E:E, "*新接*")      ' 同案件含"新接"的金额合计
X = COUNTIFS(F:F, F2, E:E, "*新接案件*")     ' 同案件"新接案件"类记录数
V = IF(E="新接案件", 1,
       IF(AND(E="新接案件-撞单", X>=2), K/W, 0))
```

照抄会踩两个边界 bug，已修正为「每案恰 1 件」：

1. **43 个案件两行都标「新接案件」**（没标撞单）→ 原公式各给 1 件，该案算 2 件。
2. **2 个案件只有 1 行却标「新接案件-撞单」**→ 原公式判 0 件，案件直接丢失。

修正规则：`X>=2` 一律按 `K/W` 拆，否则算 1 件。修正后 `Σ V = 1,115`，且**每个案件合计恰为 1**。

> **实现前必须先验证「每案合计 = 1」这个恒等式，再定稿。** 财务给的公式在边界上往往不自洽。

## 5. 咨询费：三条规则并集

| 规则 | 判定 | 条数 |
|---|---|---|
| 差旅费驱动 | `差旅费金额 > 0` | 675 |
| 主场成案 | `约见类型` 含"主场" 且 `合同总金额 ≥ 5000` | 352 |
| 直播签约 | 直播类签约 且 `合同总金额 ≥ 5000` | 58 |
| **合计（去重）** | 同条线索可同时命中多条，按线索计一次 | **1,064** |

- 月份取「约见时间」（与差旅费实收月同月率约 9 成）。
- **绝不能用 `费用支付时间` 判断是否收了差旅费**：有 3,049 行差旅费金额为 0 却填了支付时间（系统默认值），按时间判断会让咨询费虚增约 1 倍。
- 小组归属：默认「订单归属人」→ 花名册小组；`是否合作约见=是` 时改用「约见归属人1/2」按 `个数` 份额拆（均 0.5/0.5）。冲突行（非合作却填了约见归属人，38 行）**以合作标记为准**。

## 6. 区域收敛

只看 4 个主战区，其余（律师条线 + 已解散区域）合并为「其他（已解散）」放在末位：

- 不合并 → 区域合计 ≠ 财务总额，出现对账缺口。
- 合并后：A区 3,095.7 / B区 2,843.8 / C区 1,883.5 / D区 911.2 / 其他 628.3 = **9,713.7 万**，一分不差。

## 7. 口径演进（V1 → V5）

同一批数据跑了五轮，每轮都是被业务或数据打回来重做。**这段历史比最终数字更有信息量**：

| 版本 | 触发原因 | 改了什么 | 结果 |
|---|---|---|---|
| V1 | 首版 | 双源合一：咨询费/成案走订单表，收款走收入表；成案金额取首期认款 | 成案 972 件 / 5,548.7 万 |
| V2 | 确认"业绩应看收入表" | 全量切收入表；撞单按"取最大值"去重 | 7,130.6 万（**错**） |
| V3 | 业务指出撞单应相加 | 校验锚点从「首期」换成「合同总额」 | **9,713.7 万**（定案） |
| V4 | 对齐财务《成案量口径》 | 件数改为按业绩比例拆分；接入 10 月数据 | 成案 1,115 件（可为小数） |
| V5 | 反馈"小组级看不到咨询费" | 咨询费改走「人→花名册小组→区域」 | 43 个小组有咨询费，映射率 99.4% |

> V1 曾出现「1 月咨询费 256 条、2–9 月均值 90 条」的尖峰，疑为上年末订单批量录入；V2 的"取最大值"在 V3 被推翻——**能被推翻两次的口径，说明当时没有把校验基准写进文档**。这就是这份字典存在的理由。
